# 人脸识别 · 安卓版 v1.1.0

电脑版（Python，`v1.0.5\`）的全部功能在安卓上的移植：**识别 + 打卡 + 名单 + 录入抠像 + 日志 + 语音播报**。
用的是和电脑版**完全相同的三个 ONNX 模型**（YuNet 检测 / SFace 特征 / PP-HumanSeg 抠像），
所以两端的相似度数值和阈值是可以互相印证的。

> **v1.1.0 变更（本版）**
> **默认识别阈值 0.36 → 0.50**（用户反馈"0.36 误报率太高"）。0.36 是**代码里写死的默认/兜底值**
> （`FaceEngine.autoThreshold` 初值、`calibrate()` 的 fallback、`UiState.threshold` 初值、
> `resolveThreshold()` 的兜底；源头是电脑版 `engine.py` 的 `default_threshold = 0.36`），不是自动标定算出来的。
> 现在：
> * `FaceEngine.DEFAULT_THRESHOLD = 0.50f`，四处默认/兜底统一用它；
> * **自动标定也"只往上调、不往下探"**：`calibrate()` 的结果下限就是 0.50（原来能掉到 0.27）；
> * `Config.threshold` 默认值从"自动标定"(-1) 改成固定 0.50 —— **新装就是固定 0.50**，
>   设置页「自动标定阈值」默认关闭（想用老行为打开即可，打开后也不低于 0.50）；
> * 存量设置做一次性迁移：**只把"恰好等于 0.36"的旧默认抬到 0.50**，你自己拖过的其它值不动。
>
> **v1.0.9 变更**

> 弹确认框（写明这条的时间 / 类型 / 相似度 / 来源，并提示"只删这一条，其它记录不动，删完不能撤销"）→
> 确认才真删。数据层新增 `AttendanceStore.deleteRecord(id)`：按 id **精确删一条**，再把当天 CSV

## 一、装到手机上

**方式 1：adb（推荐）**

```bat
%LOCALAPPDATA%\Android\Sdk\platform-tools\adb.exe install -r app\build\outputs\apk\debug\app-debug.apk
```

**方式 2：直接把 APK 拷进手机**（微信传给自己 / 数据线复制），在手机上点开安装
（需要允许「安装未知来源应用」）。

**方式 3：Android Studio**：`File → Open` 选 `apk\v1.0.1` 目录，点绿色三角 Run。

最低系统：Android 8.0（API 26）；`targetSdk = 36`（Android 16 正式版），所以在 Android 8 ~ 16 及更高版本上都能装能跑。
CPU 架构：arm64-v8a（真机）/ x86_64（模拟器）。

## 二、第一次打开

1. 首启会把三个模型从安装包释放到应用私有目录，**要等几秒**（界面显示「正在释放模型…」）；
2. 授予摄像头权限；
3. 这时人脸库是空的，先去「录入」页：
   * **导入名单**：点「粘贴导入」，把 Excel 里的 `班级,姓名,学号` 直接粘进去；或点「选文件」选一个 CSV
     （Excel 另存的 GBK / UTF-16 CSV 都能自动识别编码）；
   * **录入人脸**：填姓名（点班级按钮选班）→ 点「用当前画面录入」，程序会取景、抠掉背景、
     存成透明底 PNG，再自动回读校验一次；
   * 也可以用「从相册选图录入」用一张现成照片，或「批量抠像录入」一次选多张
     （人名取文件名，相当于电脑版的 `--enroll-from`）。

### 识别
全屏取景 + 悬浮控件，操作和手机原生相机一致：
* 实时画面上画人脸框（绿=通过 / 橙=疑似 / 红=陌生人），框上标 `[班级] 姓名 相似度 判定`；
  设了个人阈值的人还会多标一个「·专属 0.32」；
* 顶部一排小胶囊：**阈值（点一下直接跳到「设置」页改）**、人脸库人数与 FPS、最近一次播报；
  语音如果没就绪，这里会直接显示红色提示与原因；
* 底部：左「静音/出声」、中间**大圆快门 = 保存这张画面**、右「前后摄切换」；
* 保存后弹出结果卡：快照缩略图 + 识别到的人 + 相似度，可以一键**「加进人脸库」**
  （没录入过的学生，抓一张存下来就建档了，同样按标准一寸照处理）；
* 达到阈值并**连续命中**若干帧后才播报「某某你好」（防抖），同一个人有播报冷却；
* 阈值滑杆、调试日志等都在「设置」页里，识别页上不堆控件。

### 签到
* 顶部切换**签到 / 签退**（不用新增按钮 —— 想签退就切一下模式，识别到人自动记一条）；
* 看板按班分组：应到 / 已到 / 未到 / 出席率，每个人的打卡明细；
* **签到-签退按时间配对显示**（v1.0.2）：
  * 一次进出就是 `09:00:00-09:05:00`（签到时间-签退时间）；
  * 当天只签到、还没签退 → `12:00:00-`（短横线后面空着，一眼看出"人还没走"）；
  * 一天打了多次 → 依次列出：`已到 3 次：09:00:00-09:05:00 · 12:00:00-12:03:00 · 15:00:00-`；
  * 配对规则：一个「签到」开一段，后面的「签退」收掉最近那段；没有对应签到的签退单独成段（`-15:00:00`）；
    被「撤销」的记录不参与配对；
* **筛选**有两层：
  * **状态**：应到（名单里所有人，默认）／已到（今天已有记录）／未到 —— 选「未到」就能一眼点出还缺谁；
  * **班级**：全部班级 / 某个班；
  两层可叠加（比如「一班 + 未到」）；筛完没有人的班会自动不显示，会给出「都到了 🎉」这类提示；
* 名单里没照片的人照样出现在看板（未到），**每个人名字后面直接有「补签」**（v1.0.6 起不再有「撤销」按钮）；
  （原来那个"输入姓名手动补签"的框已经去掉 —— 名字后面点一下就够了）；
* **三个导出按钮**（v1.0.2）：
  * 「导出今日」= 当天的到场点名表 CSV（含新加的「打卡明细」列）；
  * 「全部记录」= **所有日期**的原始打卡流水合成一张表，最前面多一列「日期」，Excel 里直接按日期筛；
  * 「签到签退明细」= **所有日期**的配对明细，一人一天一段一行：

  这一页是现场用的，不放不常改的开关。

### 关于抠像（无幕布人像抠像）

录入时是**无幕布抠像**：不要求蓝幕/绿幕，直接把人从任意背景里分割出来。流程是

1. **人像分割**（PP-HumanSeg 分割模型）算出「这个像素是人还是背景」的概率
2. **保留所有足够大的连通块**（面积 ≥ 最大块的 10%）—— 只留最大一块会把抬起的手臂、
   散开的头发整块丢掉
3. **闭运算**桥接头发丝那种细小断裂
4. **内缩 + 软羽化**：把紧贴轮廓的一圈背景色让掉，边界平滑过渡
5. **边界去色**：只在「轮廓带」里、且只对**半透明像素**，把颜色接近背景色的那些再压低。
   这一步专门清掉轮廓上的白边/背景亮边；因为不动实心像素，脸上的高光不会被误伤
6. 按设置合成到 白/蓝/红/透明 底，或做成标准一寸照

> 实测对比（用你自己的照片跑同一套模型 + 同一个合成公式，放大看轮廓）：
> 不做第 5 步时，头发和肩膀外圈会留一整条背景色的亮边；做了之后边缘才干净，
> 而且脸没有被压灰。这两版的对比图我是在本地渲染出来逐张看过的。

要是某张照片效果不理想：

| 情况 | 调整 |
| --- | --- |
| 轮廓上还留背景色 / 有亮边 | 设置 → 证件照 → **边缘收紧** 调到 3.0~4.0 |
| 边缘发硬、有锯齿 | **边缘羽化** 调到 3~4 |
| 头发被啃掉一圈 | 边缘收紧调小到 1.0~1.5 |
| 分割明显不对劲（人像缺块/多块） | 设置 → **抠像去背景** 关掉，改成只裁切（适合本来就对着白墙拍） |

### 抠像出问题时的排查顺序（重要）

**先看「录入」页画面上的那个胶囊**：它会显示

```
抠像 开 · 人像分割模型           ← 正常
抠像 开 · GrabCut（模型未加载）   ← 分割模型没加载成功，只能退化处理
⚠ 抠像已关闭，录出来是矩形        ← 红底警告：设置里把「抠像去背景」关掉了
```

**如果录出来是一整块矩形（没有人的轮廓）**，说明抠像那一步没生效。按顺序查：

1. **设置 → 证件照与录入 →「抠像去背景」是不是被关掉了？**
   关掉=只裁切、背景保持原样，出图就是矩形、而且是瞬间完成（不跑模型）。
   界面上那个红色胶囊也会提醒。
2. 点 **「抠像自检」**（同一张卡里）。它拿当前画面跑一遍抠像，直接给出：
   * 抠像开关：开 / 关
   * 分割模型：已加载 / 未加载
   * 实际走的方法（pphumanseg / grabcut / none）
   * **耗时**（只有几毫秒说明模型根本没跑）
   * **前景占比**（≈100% 就是"等于没抠"）
   * 一句结论：正常 / 几乎是整块矩形 / 模型没加载 / 开关是关的
3. 把自检结果或 **导出诊断包**发我 —— 有这几行就能一次定位，不用再猜。


它是设置 → 诊断与日志 → **「导出诊断包（日志 + 录入过程图）」**，一个 zip 里有三样：

| zip 里的内容 | 说明 |
| --- | --- |
| `诊断.txt` | 运行日志（含 `[抠像] pphumanseg 完成，前景占比 42%` 这类行）、语音自检、崩溃日志、抠像参数 |
| `录入过程图/…_1原图.jpg` | 取景框里的原图 |
| `录入过程图/…_2掩码.png` | **抠像掩码（白=人像、黑=背景）← 最能说明问题** |
| `录入过程图/…_3抠像.jpg` | 抠像结果合成到深灰底 |

点一下就会弹出分享，直接发出来即可。过程图也可以自己取：
`/sdcard/Android/data/com.facedemo.app/files/logs/enroll/`（文件管理器或插电脑都能进）。

拍摄建议（对无幕布抠像影响很大）：**人离背景远一点**（≥1 米）、光线均匀别逆光、
别穿和背景同色的衣服、别让背景里有大面积皮肤色/白色物体。

### 录入
全屏相机取景（和识别页同一套原生相机体验），只管拍人脸这一件事：
* 中间虚线取景框，人脸大小合适时变绿并提示「可以拍了」；底部大圆快门，
  左右分别是「相册选图」和「前后摄切换」；
* 顶部显示当前要录的人（点一下换人 / 挑下一位待录入 / 跳到名单页），
  选人框里有**搜索框 + 班级筛选**（待录入的人多时不用翻）；
  这个框原来是 MIUIX 的 `SuperDialog`，它内部把内容宽度写死限制在 420dp 还要再减两侧外边距，
  手机上实际只有约 300dp，人名和班级挤在一起 —— 现在改成**同样样式的自绘卡片**，
  宽度放到屏宽的 94%；框里的「姓名 / 班级」并排成一行、高度固定 52dp（跟随界面缩放），
  用 placeholder 而不是浮动 label（矮框里浮动 label 会飘到输入文字上、把姓名挡住），
  不再让三个输入框各占一整行、白吃掉半个卡片的高度；
* 拍完自动抠像并合成 **标准一寸照（25×35mm，295×413 像素）**，
  取景按证件照国标：**先量出实际头高（发顶→下巴），再缩放到占照片高度 60%、
  发顶距上边 8%、水平按脸中心居中** —— 比“按脸框固定倍数放大”靠谱，
  不会出现头顶贴边、肩膀看不见；背景可选白底 / 蓝底 / 红底 / 透明底，
  输出规格也可切回「原始抠像」；
* 结果卡上「重拍」会删掉刚存的那张，「下一位」自动跳到名单里下一个没录的人；
  这两个按钮放在**照片右侧的右下角**，而且**颜色是写死的高对比色**：
  实心主题色（下一位）+ 半透明白描边（重拍）。
  （踩过的坑：原来用 MIUIX 的 `TextButton`，在这张深色卡片上文字会显示成黑色 → 按钮"看不见"；
  识别页的快照结果卡同理，也已经改用同一套按钮 `Common.kt` 的 `OnDarkPillButton`。）
* 名单录入、导入、删除、人脸库管理都在隔壁的「名单」页。

### 名单
只管名单和人脸库，不碰相机：
* **筛选**：搜索框（姓名 / 学号 / 班级都能搜）+ 班级标签 + 「只看待录入」，
  列表上方直接显示「共 N 人，筛选后 M 人」；
* 填姓名 + 「班级 / 备注」—— **这一栏不做任何限制**，写「一班」「高一(3)班」「科任老师」都行，
  会原样出现在看板和导出的点名表里；留空记为「未分班」；
* **点名字 → 直接跳到「录入」页并选中他**，右侧还有 **三个纯图标小圆钮**：
  **相机（去录入）/ 笔（改班级·备注·学号·个人阈值）/ 垃圾桶（删除）**。
  为什么不用文字：一行里放三个带文字的按钮时宽度不够，文字会被挤得裁掉（图标还在、字没了），
  这三个动作看图标就懂，所以直接做成图标（带无障碍描述，TalkBack 会读出来）。
  人脸库列表里的「管理」同样改成笔图标，和管理对话框一一对应；
* **个人阈值**：点「改」里可以只给某一个人定一个相似度阈值 ——
  **填了就只对这个人生效**（越大越严、越小越松），**留空就和大家一样用全局阈值**。
  典型用法：某个学生总是差一点点才到阈值（照片少、戴眼镜、光线暗），
  给他单独填 0.32 就行，不用为了他把全班的阈值都降下来；
  反过来，双胞胎/长得像的人老误识，也可以只把他调高。
  设过的人会在名单里用主题色标出「阈值 0.xxx」，识别页的人脸框上也会标「·专属 0.32」，
  方便现场核对；删掉这个人时他的专属阈值会一起清掉。
  （存在 `person_thresholds.csv`，两列：姓名,阈值 —— 电脑版不认识这个文件，也不会受它影响）
* **删除**确认框里可以选「只移出名单」（照片保留）或「连照片一起删」。删掉的人会被记进
  `roster_removed.txt`，**不会被“有人脸照片就自动入册”的逻辑再加回来**；以后重新导入名单 /
  重新录入他就自动恢复，也可以在名单卡片里点「恢复自动入册」一次性恢复；
* 名单导入支持粘贴或选文件（GBK / UTF-16 自动识别，表头自动映射列）；
  **没有表头时也不卡内容** —— 「科任老师,张三,2026001」这种自由文字会被当成标签，
  多出来的列会并入备注而不是丢掉；
* 人脸库区列出每个人及其照片，点「管理」可逐张删除、改班级、从名单移除。
  **「管理」对话框的上半部分是原图**（一人一张就够：只显示第一张，**名片大小 96×134dp**、
  按一寸照 25:35 比例完整显示，旁边是文件名 + 大小 + 「删除这张」+「**保存到本地**」）；
  重复录入攒下多张时会多一个「**只保留这一张**」按钮，一键清掉多余的。
  下半部分才是班级/学号/**个人阈值**和「保存 / 去录入 / 删除这个人」，整个对话框内容可滚动。
* **保存到本地**（v1.0.2）：把这张人脸库照片存进系统相册 —— Android 10 及以上写
  `Pictures/人脸识别/`（走 MediaStore，**不需要任何存储权限**，保存完在图库 App 里就能看到）；
  更低版本因为没有存储权限，退回写应用外部目录 `Android/data/com.facedemo.app/files/Pictures/人脸识别/`，
  提示里会给出完整路径（文件管理器/插电脑可取）。
* **导出人像包**（v1.0.2）：人脸库卡片上的第三个按钮，把 `photo/` 下采集到的所有人像（含班级子目录）
  打成一个 zip，里面另附 `人像清单.csv`（姓名/子目录/文件/字节）和 `readme.txt`；
  生成后直接调系统分享（发微信、存网盘都行）。只要人像时用它；
  需要名单+日志+快照的完整备份还是用「设置 → 数据备份与恢复 → 导出备份」。

> **「导入照片」有两条路，别选错**：
> 「导入照片（原样）」= 把相册里的图直接拷进人脸库，**不抠像、不换底、不做一寸照**；
> 「导入并抠像成一寸照」= 走和相机录入一样的流水线，按设置里的规格处理。
> 想验证背景设置有没有生效，用后者，或直接在「录入」页按快门。

**「设置」是底部导航栏的第五格（在「名单」后面）**，整页铺开、没有「完成」按钮，点别的格子就走：
顶部一张摘要卡直接写明
**「录入输出：标准一寸照 25×35mm（295×413 像素）· 白底」**并配一个 25:35 的小预览，
**下面还会显示 `v1.0.1 · 构建 0919-0250`** —— 这是"构建标记"（`ui/Theme.kt` 的 `APP_BUILD`，每次出包手动更新），
用来一眼确认手机上装的是哪一次构建（同一个版本号下改了十几轮界面，光看版本号分不清）。
「诊断与日志」里的「版本」也会带上它。
下面按主题分卡：识别 / 省电与发热 / 语音播报 / 证件照与录入 / 界面 / 数据备份与恢复 / 诊断与日志。
**选项按钮选中是实心、未选中是描边**，一眼能看出当前选的是哪个。

一行里的几个按钮现在是**平分整行宽度**（不再因为"每个按钮有个最小宽度"而被顶到第二行、还左对齐）；
文字实在放不下时会自动缩一点字号，不会换行也不会把字切掉半截。

设置里还有：识别（阈值 / 自动标定 / 检测置信度 / 帧宽度 / 重建引擎 / 日志开关）、
语音（开关、音频流、语速、音调、音量、**音色下拉框**、试播、静音、重新初始化 + 一键自检并排、三套模板、冷却与防抖）、
证件照（输出规格、背景、取景外扩、替换旧照片、回读校验、自动下一位）、
省电与发热（放平暂停、识别频率）、界面（缩放 + **主题色**）、诊断（版本 / 抠像 / OpenCV / 路径 / 运行日志 / 崩溃日志 / 分享诊断 / 分析相似度）。

### 滑杆的分度（拖得准）

识别那张卡里的三个滑杆都设了**分度**，拖动是一格一格停的，不会手指一动就跳好几个值：

| 滑杆 | 分度 | 一共几格 |
| --- | --- | --- |
| 相似度阈值 | 0.025 | 30 格（0.150 → 0.900） |
| 检测置信度 | 0.05 | 11 格（0.40 → 0.95） |
| 识别帧宽度 | 64 px | 15 格（320 → 1280） |

### 主题色（可自定义）

设置 → 界面 → **主题色**：6 个预设圆点，点一下全界面立刻换色（按钮、开关、滑杆、选中态、卡片高亮都跟着走）：

| key | 颜色 |
| --- | --- |
| 极光蓝（默认） | `#3388FF` |
| 青碧 | `#00B0A6` |
| 森绿 | `#2AA45C` |
| 紫罗兰 | `#7C5CFF` |
| 琥珀 | `#F08A00` |
| 玫瑰 | `#EE4B6A` |

实现方式：由主色用 `lerp` 推出 MIUIX 色板的**主色家族**（primary / onPrimary / primaryVariant /
primaryContainer / disabledPrimary* / secondary 家族），**背景、卡片、文字、错误色保持 MIUIX 原样** ——
所以换色只换强调色，不会把界面的明暗关系搞乱；深色模式也各有一套（说明见 `ui/Theme.kt`）。

### 状态栏 / 系统栏（白边与图标明暗）

* **根因（v1.0.1 修）**：MIUIX 的 `Scaffold` 默认 `containerColor = surface`（浅色下就是"白"），
  并且默认把 `contentWindowInsets`（systemBars）应用到内容区 —— 于是内容上下永远空出系统栏那两条，
  露出白底：**dock 下面那块"白块"就是它**，它同时也把 dock 顶高了（内容区被缩进、dock 又在内容区里）。
  现在显式传 `contentWindowInsets = WindowInsets(0,0,0,0)` + `containerColor = 背景色`，
  内容区不再被系统栏挤，insets 由我们自己控制。
* **dock 位置**：dock 挂在**最外层全屏 Box** 上（不在页面内容里），所以它在五个页面上的位置**完全一致**；
  页面内容自己让开顶栏（`.padding(top = padding.calculateTopPadding())`）和 dock（底部留 84dp + 手势条）。
* 顶栏与它上面的**状态栏那一条**用同一个 `surface` 颜色铺满，下面压一条 1px 分隔线 ——
  这样状态栏和内容之间才有层级，不会"白上加白糊成一片"；
* **状态栏图标逐页自适应**：识别页是相机铺满 + 顶部压暗的黑画面 → 用**亮色图标**；
  其余页面浅底 → 用深色图标（深色模式反过来）。手势条图标一律跟随系统深浅色。
* 识别页是相机铺满到状态栏的，所以顶部额外压了一层 96dp 的黑→透明渐变，
  保证状态栏上的时间和电量在亮画面（比如白墙）上也看得清；
* 主题资源补齐了 `values-night`（原来是单套写死深色，浅色模式冷启动会闪黑边）。
* **dock 形态（v1.0.1 定稿）**：**四角都圆**的玻璃条，**左右各留 14dp 边距**
  （全面屏的屏幕圆角会裁掉贴边内容），高度**由内容决定**（不再写死 50dp —— 系统字体一放大，
  文字下半截就会被裁掉），手势条区域 **透明**（下面露出的就是页面底色/相机画面）。
  * 指示器与光泽层用 `Modifier.matchParentSize()` 跟着内容尺寸走，所以文字放大也不会裁；
  * 高度仍然是**实测**的（`onSizeChanged`，界面缩放放大后它会变高），页面据此留底部空间。
* **dock 动效（液态感，四个）**：
  1. **滑动指示器**：选中项背后一块**实心主题色**胶囊（跟着你选的主题色），换页时 spring 滑过去，
     中途**先拉长到 1.5 倍再弹回**（液态拉伸）；选中项的图标/文字用 `onPrimary`（白），
     坐在实心胶囊上清清楚楚。
     （踩过的坑：先是白色胶囊 → 白玻璃上看不见；再是 30% 透明度的主题色 → 还是几乎看不见，
     所以现在用实心主题色 + 白字。）
  2. **图标动效**：选中放大到 1.26 倍、未选中缩到 0.92 倍 + 颜色渐变；
  3. **光泽扫过**：一条很淡的高光每 5.2 秒缓慢扫过整条玻璃（无限循环）；
  4. **入场**：冷启动时整条 dock 从下方 56dp 上滑淡入。

### 卡片里控件的间距（"上下按钮边缘相接"的根因）

`SectionCard` 自己带 `spacedBy(12dp)`，但它**直接子节点只有一个** —— 页面里普遍又套了一层
`Column { ... }`，那一层没有间距，于是卡片内所有控件（滑杆、开关、按钮行）之间间距是 0，
表现就是"上一行按钮的下边缘和下一行按钮相接"、"识别帧宽度滑杆和重建引擎贴在一起"。
v1.0.1 把所有 `SectionCard` 里的这层裸 `Column` 都补成
`Column(verticalArrangement = Arrangement.spacedBy(12.dp))`（设置页 7 处、签到页 1 处），
间距恢复成统一的 12dp。

## 五、自己重新编译

双击 `build_apk.bat`（脚本里已经配好 JDK / SDK / Gradle 路径），或者手动：

```bat
set JAVA_HOME=C:\Program Files\Android\Android Studio\jbr
set ANDROID_HOME=%LOCALAPPDATA%\Android\Sdk
set ANDROID_USER_HOME=..\_tools\android-home
set GRADLE_USER_HOME=..\_tools\gradle-home
..\_tools\gradle-9.5.0\bin\gradle.bat -p . assembleDebug
```

想减小体积（只要真机）：调试包默认带 `arm64-v8a` + `x86_64`（模拟器用），
`app\build.gradle.kts` 的 `debug` 块里去掉 `x86_64` 即可小一圈。

> ABI 有个坑：AGP 会把 `defaultConfig` 和 `buildType` 里的 `abiFilters` **取并集**，
> 所以在 buildType 里 `clear()` 是无效的（一开始就是踩了这个坑，release 包里还带着 59 MB 的
> x86_64 版 OpenCV）。这里的写法是 `defaultConfig` 只放 `arm64-v8a`、`x86_64` 只在 `debug`
> 块里追加，release 自然就只有 arm64。

### 出正式包（release，已签名、已混淆）

**推荐：双击 `build_release.bat`**（也可以 `powershell -ExecutionPolicy Bypass -File build_release.ps1`）。
这个脚本把出正式包该做的事全串起来了，省得手敲 gradle 再自己一项项看结果：

| 步骤 | 做什么 |
| --- | --- |
| 1 环境检查 | JDK（Android Studio 自带 JBR）/ Android SDK / build-tools（自动取版本号最高的）/ Gradle / 签名证书，缺哪个直接报错退出 |
| 2 版本与构建标记 | 读 `versionName`/`versionCode` 与 `APP_VERSION`/`APP_BUILD`；**默认把 `APP_BUILD` 自动改成当前 `月日-时分`**，并检查 `APP_VERSION` 与 `versionName` 是否一致（不一致就报错，避免设置页显示的版本跟安装包对不上） |
| 3 编译 | `gradle assembleRelease`，输出同时写进 `dist\build-<标记>.log` |

## 五之二、省电与发热（相机策略）

手机做实时人脸识别时，**相机采集 + 逐帧推理是整机最耗电、最发热的部分**，这一版专门做了三层控制：

1. **放平自动停相机**（设置 → 省电与发热 → 「手机放平时暂停相机」，默认开）
   用重力传感器算「重力沿手机屏幕竖直方向的分量占比」判断姿态：
   占比 < 0.40 认为放平 → **整个相机解绑**（预览和分析一起停，这才是真正省电的一步）；
   占比 > 0.55（迟滞，避免临界角度反复启停）认为举起来了 → 自动恢复。
   识别页/录入页会盖一层「手机放平，相机已暂停」的提示，举起来自己就消失；
   想临时继续用可以点提示里的「继续使用」，重新举起后该临时覆盖自动失效。
   重力传感器是低功耗硬件传感器，监听它本身几乎不耗电。
2. **限制识别频率**（设置 → 省电与发热 → 「识别频率」，默认约 8 次/秒）
   相机照样按 30fps 出预览（画面流畅），但**只有到设定间隔的帧才会被转成位图送去检测**，
   中间的帧直接丢弃 —— 连位图转换都不做，省掉大量 CPU 和 GC，这是降温最明显的一项。
3. **只在相机页开相机**：切到「签到」页、打开设置页、或者在「名单」页改名单时，
   相机整体解绑（预览 + 分析都停）—— 这些页面根本不需要画面，尤其改名单常常要弄好几分钟，
   一直开着纯属白耗电。回到「识别」/「录入」页立刻重新起相机。
4. **相机跟随生命周期**：切到后台、退到桌面时 CameraX 自动解绑，不再空转。

## 六、界面与主题（MIUIX / HyperOS 设计体系）

界面用的是小米开源的 **MIUIX**（`top.yukonga.miuix.kmp:miuix`，Apache-2.0），也就是 HyperOS 的设计体系：

* **主题**：`FaceDemoTheme` 先套 MIUIX 主题，再把 MIUIX 的色板**搬进 MaterialTheme**，
  两套组件用同一个色板，不会两个色系打架
* **外壳**：MIUIX `Scaffold` + `SmallTopAppBar` + **悬浮导航栏**；
  底栏（dock）在 v1.0.1 换成了**液态玻璃质感**的自绘胶囊：半透明渐变 + 上缘高光描边 + 柔和外阴影 + 26dp 圆角，
  识别页相机铺满时它就是"浮在画面上的一层玻璃"。
  （说明：真正的**背景模糊**（backdrop blur）在 Android 上要么得用 `RenderEffect` 抓窗口背景 ——
  抓不到 CameraX 的预览 Surface，要么用 Android 12 的窗口模糊 —— 那会把整个窗口一起糊掉；
  所以这里是"视觉上的玻璃"，不是真的把背后的画面做高斯模糊。）
* **组件**：卡片 / 按钮 / 开关 / 滑杆 / 对话框 / 表面全部是 MIUIX 实现
  （16dp 圆角 + G2 连续曲率、HyperOS 主色与按压反馈）
* **实现方式**：`ui/Miuix.kt` 里用 MIUIX 写了**同名包装**（`Button`/`OutlinedButton`/`TextButton`/
  `Card`/`CardDefaults`/`Switch`/`Slider`/`AlertDialog`/`Surface`），各页面把
  `androidx.compose.material3.*` 的 import 去掉即可，调用点一行都不用改
* **仍是 Material3 的部分**（后续可继续迁移）：`Text`（引用最多、换成 MIUIX 收益小风险大）、
  `OutlinedTextField`（MIUIX 的 TextField 用字符串做 label，API 差异较大）、
  `CircularProgressIndicator`、`Snackbar`

APK 体积因此从 138.5 MB 涨到 144.3 MB（+5.8 MB 是 MIUIX 及其依赖）。

### 界面缩放（字号 / 控件大小不合适时）

不同手机的系统字体缩放、屏幕宽度差别很大，界面可能偏小或偏挤。设置页最下面 **「界面」** 卡片里有
**「界面缩放」**：四个整档按钮（小 0.85× / 标准 1.00× / 大 1.15× / 特大 1.30×）加一根 **「微调」** 滑杆
（0.75× ~ 1.40×），改完立即生效。它改的是 Compose 的 `LocalDensity`，
**字号、图标、间距、控件高度会整体等比缩放**，不是只放大文字。

实现上有一处容易踩的地方：缩放层（`UiScale`）在 `FaceDemoApp` 里**包住了「设置页」和「主界面」两个分支**，
而且当前缩放值放在 `UiState.uiScale` 里（是 Compose 能观察到的状态）——
所以在设置页里拖这根滑杆，**设置页自己也会当场跟着缩放**，不用退出去再进来看效果。

### 按钮不会互相挤（按钮行会换行）

原来一排按钮用的是「等分宽度」(`Row` + `Modifier.weight(1f)`)。字号或界面缩放一大，
文字就被压成半截，相邻两行的按钮看着还互相挤。现在所有按钮行都走 `Common.kt` 里的 **`BtnRow`**：

* 每个按钮**按自己的文字取宽度**（`OptionButton` 有 84dp 下限，普通按钮 120~140dp 下限）；
* 一行放不下就**自动换行**（Compose 的 `FlowRow`），永远不挤压、不硬切字；
* 按钮文字统一「单行 + 省略号」，万一位子不够也是 `…` 而不是切掉半个字。

底部悬浮导航栏的 5 个图标每格**等分宽度**（各 1/5），不会因为缩放而挤成一团。

设置页「识别」卡片里，**「自动标定阈值」开关挪到了「相似度阈值」滑杆上面**：
打开自动标定时阈值由人脸库算出（滑杆置灰不可拖），关掉才由滑杆手动定 —— 开关在上、受它控制的滑杆在下，顺序跟逻辑一致。

## 十、语音（TTS）没声音：怎么查 + 日志怎么给我

### ★ 已定位到根因（真机自检结果）

你发来的自检里最关键的一行是：

```
系统引擎: （一个都没找到）      ← 手机里明明有 TTS 引擎
引擎: （未初始化)   后端: 不可用
播报调用: 0 次
```

这是 **Android 11+（API 30）的「软件包可见性」限制**：targetSdk ≥ 30 的应用默认
**看不到其他应用**，而 `TextToSpeech` 内部正是靠 `PackageManager` 查询 TTS 引擎服务来选引擎的。
查不到 → 一个引擎都枚举不出来 → 连系统默认引擎都初始化失败 → App 完全不发声
（而系统设置里的「试听」是系统自己的应用在做，有完整可见性，所以那边正常）。

**修法**：在 `AndroidManifest.xml` 里声明

```xml
<queries>
    <intent>
        <action android:name="android.intent.action.TTS_SERVICE" />
    </intent>
</queries>
```

这一版已经加上（可在 APK 清单里查证）。之前我自作聪明做的「多引擎回退」之所以没救回来，
就是因为枚举结果本身就是空的。另外新增：设置里可以**手填 TTS 引擎包名**
（例如 `com.google.android.tts`），万一某些 ROM 仍然枚举不出来还能指定。

装上新版后请再点一次「一键自检」，这两行应该变成「引擎: 系统默认引擎 / 就绪」以及列出引擎列表。

### 启动时不播报、非要去界面上点一下才好？（已修）

如果你遇到「打开 App 后一直不播报，去识别页按一下静音/出声按钮、或者进设置动一下开关才开始响」，
那是两个原因叠在一起，新版都处理掉了：

1. **引擎是异步初始化的**，而界面上的「当前状态」只在改动设置时才刷新 —— 所以引擎其实已经好了，
   界面还显示「未就绪」，你会以为必须点一下。现在启动后 1.5 秒 / 5 秒各自动刷新一次状态，
   并在运行日志里留一行 `[语音] 启动自检: 状态=…, 就绪=…, 开关=…, 静音=…, 模式=…, 引擎=…`。
2. **`ready / muted / dryRun / 引擎引用` 之前不是 `@Volatile`**：这几个字段是**相机分析线程**在读
   （`speak()` 就在那条线程上被调用），写它们的却是主线程。缺少内存屏障时分析线程可能一直读到旧的
   `ready=false`，表现正是「不点一下就不播报」。现在全部加了 `@Volatile`。
3. 另外两个兜底：引擎若 `onInit` 一直不回调（个别 ROM 会这样），启动 5 秒后**自动重新初始化一次**，
   不用你去点「重新初始化语音」；初始化那几秒里如果已经识别到人，那句问候会**攒下来、引擎好了立刻补播**，
   不再被吞掉。

> 还是没声音的话，把 设置 → 运行日志 里 `[语音]` 开头的几行发我，尤其是那行「启动自检」——
> 它会直接写明是"开关关着"、"静音着"还是"引擎没就绪"。

### 另外两点（你自检里已经看到）
* `通知音量: 0 / 16` —— 你确实把通知音量关了。如果系统把你的 TTS 走**通知流**，那就会没声音。
  设置里「播报音频流」保持**默认**，或依次试媒体/系统。
* `音频流: 系统` —— 你之前选的是「系统」流，这个流经常被系统压低甚至静音，
  修好引擎后建议先切回**默认**再试。

### 第一步：点「一键自检」（设置 → 语音播报 → 蓝色按钮）

它会做三件事，并把结论写在最后一行：

1. 让引擎把「测试一下，张三你好」**合成成一个 wav 文件**（`synthesizeToFile`）
2. 用系统播放器播放这个 wav
3. 再试一次引擎直接播报（`speak()`）

这一步能把两种情况**彻底分开**：

| 自检结果 | 含义 | 怎么办 |
| --- | --- | --- |
| ② 显示「生成了 xx 字节 → 引擎能出声，问题在【播放环节】」 | 引擎正常，是播放被静音/走了别的流 | 按③听有没有声；没声就查媒体音量、换音频流、换音色、断开蓝牙；也可以一直用「合成后播放」模式 |
| ② 显示「没有生成有效文件 → 引擎【本身合成失败】」 | 引擎真的出不了声 | 多半没装中文语音包（设置→语言与输入→文字转语音），装完点「重新初始化语音」；或换引擎 |
| ① 返回码不是 0 | 引擎直接拒绝了这个请求 | 点「重新初始化语音」；把自检结果发我 |

## 十一、闪退怎么办（已修的四类问题 + 排错办法）

## 十一、闪退怎么办（已修的四类问题 + 排错办法）

### 已修 #1：OpenCV 原生库没加载 → 一打开就闪退

`org.opencv:opencv:4.13.0` 这个官方 AAR 的 `AndroidManifest.xml` 里只有一个 `uses-sdk`，
**没有任何自动初始化**，必须在用到第一个 OpenCV 类之前手动调用 `OpenCVLoader.initLocal()`。
之前漏了这一步，第一次碰 `Dnn.readNetFromONNX` / `Mat` 就会抛 `UnsatisfiedLinkError`；
它是 `Error` 而不是 `Exception`，`catch (Exception)` 接不住，线程默认处理器直接杀进程。
现在在 `MainActivity.onCreate` 里先加载原生库（三级兜底），加载失败也只会显示一行错误提示。

### 已修 #2：位图通道数不对 → 载入人脸库时闪退

真机（OnePlus / Android 16）上的第二条崩溃日志：

```
org.opencv.core.CvException: Number of input channels should be multiple of 3 but got 4
  at FaceDetectorYN.detect → FaceEngine.detectMat → FaceEngine.loadGallery
```

`Utils.bitmapToMat()` 对 Android 的 **ARGB_8888** 位图会生成 **4 通道 RGBA** 的 Mat，
而 YuNet 检测、SFace 特征、PP-HumanSeg 抠像、GrabCut 全都只接受 **3 通道**
（电脑版用 `cv2.imread` 读进来天生就是 3 通道 BGR，所以那边碰不到这个问题；
而手机上的照片、尤其带透明通道的录入结果 PNG，解码出来就是 4 通道）。
现在所有 Bitmap→Mat 都走统一入口 `MatUtil.toBgr()`（`core/OpenCv.kt`），
统一转成 BGR —— 通道顺序也和电脑版一致，两端的相似度数值才对得上。

顺带修的相关问题：

* **手机拍的照片会躺倒**：`BitmapFactory` 不理会 EXIF 方向，只用 EXIF 记录方向的竖拍照片
  解码出来是横的，人脸检测会明显变差。现在 `ImageUtil` 会读 EXIF 并转正（读不到就按原样，
  不会更糟）；人脸库加载也改走同一条解码路径。
* 检测结果子矩阵（`faces.row(i)`）之前在循环里没释放，长时间跑会慢慢泄漏原生内存，已修。

### 已修 #3：解读 YuNet 检测结果时数组越界 → 载入人脸库/录入都失败

真机第三条崩溃日志：

```
java.lang.ArrayIndexOutOfBoundsException: length=1; index=1
  at FaceEngine.detectMat(FaceEngine.kt:122) → FaceEngine.detect → loadGallery
```

YuNet 在 Java 侧返回的是一张 **N×15 的单通道 CV_32F 矩阵**（实测确认：`shape=(1,15) dtype=float32`，
前 4 列是 x/y/w/h，中间 10 列是 5 个关键点，最后一列是置信度）。
坑在于：**单通道 Mat 的 `get(r, c)` 返回的是长度 1 的数组**（就 (r,c) 那一个数），
不是 `[x, y, w, h]` 四个数 —— 按 `box[1]` 取就直接越界。
现在改成一次性整块读成 `FloatArray` 再按行切（顺带比逐元素 `get` 快很多），
并且把整行（框 + 关键点）一起按缩放比例换算回原图坐标、置信度不参与缩放。

### 已修 #4：切到「录入」页后相机被关掉 → 用摄像头录不进人脸

相机对象原来建在识别页里，切页时随页面一起销毁，「用当前画面录入」拿到的是**冻结的旧帧**
（画面里往往已经没有人脸），所以怎么点都录不进去。
现在相机提升到 App 层（切页不销毁），并且**录入页也加了取景画面 + 人脸框**，
画面上直接显示「画面里 N 张人脸（可以录入了）」，不用再盲拍。

### 顺带加固（避免一张照片拖垮整个 App）

* **单张照片出错只跳过这一张**：人脸库加载时每张图单独兜底，坏图/超大图/损坏文件会被跳过
  并在日志里列出原因，不会让整个初始化失败；
* **重载/重建不再变成整页「初始化失败」**：`重载人脸库`、`重载名单`、`重建引擎` 都各自兜住异常，
  失败只在提示里显示原因，引擎本身仍可继续用；
* 因此「录入名单后提示初始化失败」这条也一并解决了 —— 名单导入本身没问题，
  是导入后自动重载人脸库时踩到上面那个越界。

### 万一还闪退

程序已经装了崩溃收集器，会把完整堆栈写到两个地方并弹一个说明页：

| 位置 | 怎么拿 |
| --- | --- |
| 崩溃说明页 | 闪退后会自己弹出来，点「分享日志」直接发给开发者 |
| `设置 → 崩溃日志` | 里面有「查看完整日志 / 分享给开发者 / 清除」 |
| `/sdcard/Android/data/com.facedemo.app/files/crash_时间戳.txt` | 文件管理器或插电脑直接拷 |
| `/data/data/com.facedemo.app/files/crash_last.txt` | 应用私有目录（也能从设置页看） |

日志里带机型、Android 版本、CPU 架构、异常类型和完整堆栈 —— 把这段发出来就能定位。
到目前为止的四类问题（原生库没加载、位图 4 通道、YuNet 结果解读越界、相机随页面销毁）
都是靠这份日志一次定位的。

## 十二、已知限制（如实说明）
* **语音和摄像头没法在开发环境里验证**：本次只验证到「编译通过 + APK 结构正确」，
  真机上的声音、画质、识别速度需要你自己跑一下确认；如果听不到声音，
  去 手机设置 → 无障碍/语音合成（TTS）确认已安装中文语音，或在设置页点「试播一次」看提示。
* 首次识别要在模型释放完成之后（界面不再显示「正在释放模型…」）。
* 自动阈值需要**至少两个人**（每人至少两张照片）才标得准，单人库会用官方推荐的
  0.36 × 0.75 作下界 —— 与电脑版行为一致。
* 打卡/相似度日志按天分文件，跨天会自动切换（程序在后台放一夜也没问题）。
